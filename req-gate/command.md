你是需求门检查者。对以下任务描述执行一次门控判定，不得跳步，不得迭代。

任务描述：$ARGUMENTS

## 判定流程

1. **Trivial 判定**：≤1 文件且 ≤20 行且行为明确 → 输出 `PASS(trivial)`，可直接开工。
2. **非 Trivial → 7 维快检一次**：用 task 工具派生一个规划评审型子代理执行下表（opencode: subagent_type="metis"；无该 agent 或 task 工具不可用时由你本人执行）。每个维度**必须**给出显式判定（适用/不适用+结论），不许略过：

   | # | 维度 | 探问 |
   |---|------|------|
   | 1 | 输入域 | 空值/极值/非法类型/超长输入时的行为？ |
   | 2 | 状态域 | 首次使用/已有旧数据/数据迁移？ |
   | 3 | 错误路径 | 失败时报错格式/回滚/重试？ |
   | 4 | 并发与时序 | 同时操作/重入/中断恢复？ |
   | 5 | 权限与边界 | 谁能做/越权/多租户隔离？ |
   | 6 | 兼容与迁移 | 旧版本/旧调用方/依赖版本？ |
   | 7 | 观测与验收 | 怎么证明做对（日志/指标/测试断言）？现有测试覆盖了哪些、需新增/补充哪些用例？ |

3. **三梯判定（问是最后手段）**——对每个"适用且描述不清"的维度按序取第一梯：
   - **调研梯**：读代码/文档/既有模式/项目惯例/只读探查命令——能定 → 记「来源=调研」+ 依据（文件:行 或 命令输出），不问任何人；
   - **默认梯**：调研不能定但存在安全可逆默认 → 记「来源=默认」+ 默认内容与推翻方式，不阻塞；
   - **需问梯**：仅当 ①调研穷尽 ②无安全默认 ③属用户所有（不可逆/破坏性/安全/产品对外契约）三条件**同时**成立 → 记「来源=需问」，进第 5 步。

   **禁止项**：凡仓库、文档、构建系统、项目惯例、只读探查能回答的问题，一律不得进入「需问」。
4. **零共享批评步**（2026-11-21 加；恰好一轮，禁与批评者多轮对话）：仅当判定走向 `PASS`（非 trivial）时执行——
   1. 先拟「方案」段：2–3 行实现思路与改动面，追加在验收清单之后（批评对象）；
   2. 语义召回线索：以任务关键词+方案要点为 query 调 `memory_recall`（limit 5，全局），召回相似历史事故作批评线索；工具不可用则跳过并在 CRITIC 行注明 `SKIPPED:no-recall`；
   3. 派零共享批评子代理（opencode: subagent_type="metis"；不可用时由你本人以批评者身份执行——重读任务描述与记录全文，不带此前推理预设）：
      - 输入＝任务描述全文＋维度判定表＋验收清单＋方案段＋召回线索；不携带会话推理史；
      - **报什么**：验收清单漏覆盖的需求面（对照任务描述）；方案未考虑的边角（重点挑战判定表「不适用」行）；会在终闸需求符合性册翻车的点；召回线索疑似同型坑；
      - **禁报什么**：风格/命名/重构/可选优化、理论性极端边角、「建议换库」类、验收清单已覆盖项；
      - 每条 finding：severity(critical/suggestion)＋问题＋依据；恰好一轮收口；
   4. 处置：critical → 修订验收清单/方案段后再收口，禁带未修订 critical 进 `PASS`；suggestion → 记入 CRITIC 行可不改；
   5. 记录末尾写结论行：`CRITIC: PASS`（无 critical）／`CRITIC: REVISED`＋发现清单（critical 已修订）／`CRITIC: SKIPPED:<原因>`（批评者不可用等降级，审计可查）。
5. **快检收口**：
   - 判定表「需问」行为 0 → 输出 `PASS`：附维度判定表 + 可执行验收标准清单 + 方案段 + CRITIC 结论行（适用维度的断言入清单），建议写入会话 todo 后开工；
   - 「需问」行 ≥1 → 输出 `ESCALATE`：附完整判定表 + 需问分叉清单（每个附推荐默认），建议转 plan 规划（opencode 下 ulw-plan）；ESCALATE 不做批评步（plan 流程自有评审）。
6. **健康度自检**：判定表「来源」分布应为 调研 ≥ 默认 ≥ 需问（需问通常 0~2 行）。若「需问」≥3 行，先自查是否未调研——仓/文档/惯例能答的问题出现在「需问」即判定无效，必须回第 3 步调研梯重做后再收口。

## 记录落盘（放行凭证）

无论结论为何，将完整结论写入 `<TMPDIR 兜底 /tmp>/opencode/req-gate/<当前会话ID>.md`（目录不存在先 `mkdir -p`；会话 ID 获取方式同插件契约——实测本机会话存储中本项目目录最新会话，取不到则写 `manual-<YYYYMMDD-HHMM>.md` 并注明）。记录必须包含**维度判定表全文**（维度|适用?|结论|来源）；非 Trivial 的 `PASS` 另含**方案段**与 **CRITIC 结论行**（第 4 步产物）。该记录是 req-gate-enforcer 插件放行本会话产品编辑的凭证——不写记录，首个编辑会被拦截。（2026-11-03 起记录出仓 tmp：不再脏仓，done 门不被未跟踪文件卡住；tmp 清理致记录丢失＝重新快检一次即可，文件是证据不是状态。历史记录在旧仓内路径 `.omo/req-gate/` 与 `.req-gate/`，不迁移、仅存档。）

## 约束

- 只做一次检查，禁止自我评审循环或多轮迭代；批评步恰好一轮（独立批评者零共享，不属自我评审）。
- 不修改任何文件，不改判据真源（门控记录本身除外）。
- 输出末尾一行结论，恰为三者之一：`PASS(trivial)` / `PASS` / `ESCALATE`。
