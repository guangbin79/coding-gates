# recall-check——写后代码召回自查（判据真源）

> 2026-11-21 立制。本页为 harness 无关判据真源；环境绑定见 ../opencode/SKILL.md（真源引用、禁复制正文）。

## 写：代码指纹（经验捕获供给侧）
- 经验捕获涉代码改动时，正文末尾含一行：`代码指纹: <函数名/类名/配置键>, <涉及文件路径>`（3–7 个，粒度 符号>文件>目录）；非代码经验豁免
- 目的：代码级召回的供给侧素材——标识符随经验入库，写后自查才可命中

## 查：写后召回自查（消费侧）
- 时机：每完成一个逻辑单元（每任务约 2–3 次），进评审前
- 动作：以「一句话摘要＋关键标识符」为 query 查语义记忆库（top5，全局）；逐条对照「本 diff 是否同坑」
- 处置：命中即修；空召回/全不相关即过，禁为凑自查硬找问题；禁整段倒 diff 当 query（符号与样板稀释语义）
- 空结果先判健康：检索返回空无法区分「真没经验」与「服务故障/调用侧错误」——先做服务健康检查（绑定层定义）再判空；故障空显式上报，禁静默按「空即过」放行（2026-11-21 形状假设乌龙实证：调用侧解构错误也表现为空）
- 召回是待验证假设非判决：相似≠相同，逐条对照核实后才动作

## 边界
- 本件是写者侧动作；评审者（零共享/记忆盲区约束）不适用
- 触发粒度＝逻辑单元，非每次编辑
- 命中修掉的坑即经验捕获信号，随收尾沉淀自然入库，不为自查建台账
- 试行期主观记账命中率；连续噪声即摘除本件
